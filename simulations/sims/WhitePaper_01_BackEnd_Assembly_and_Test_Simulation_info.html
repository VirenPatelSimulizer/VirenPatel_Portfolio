DPAT vs SPAT Simulation

Semiconductor backend assembly & test quality control comparison

What is Part Average Testing (PAT)?

Part Average Testing is a statistical quality control method used in semiconductor manufacturing to identify defective units that pass standard specification limits but are statistical outliers relative to their lot. PAT catches "marginal" parts that may fail in the field despite passing absolute test limits.

There are two main approaches: Static PAT (SPAT) calculates control limits from an initial training set and applies them to all subsequent production, while Dynamic PAT (DPAT) uses a rolling window of recent lots to continuously update limits. This simulation demonstrates how each approach performs under various process disturbances.

How the Simulation Works

The simulation models the complete semiconductor backend flow:

  • Lot Generation: Each lot contains multiple units with normally distributed measurement values (e.g., Iread current), parameterized by baseline mean and sigma.
  • Process Flow: Units flow through Material Source → Assembly → Transport → Tester → Ship or Destruction. Each stage can add variation.
  • Measurement Model: The measured value combines the innate part value with calibration error, thermal effects, firmware effects, and random noise.
  • SPAT Limits: Calculated once from training lots as mean ± kσ. Fixed for all subsequent production.
  • DPAT Limits: Recalculated using a rolling window of recent lots, adapting to process drift. Can be stratified by test conditions.
  • Defect Injection: Intermittent defects are injected with configurable probability, simulating real-world failure modes.

Key Equations

PAT control limits:

Upper Limit = μ + k × σ
Lower Limit = μ - k × σ

Where μ is the mean, σ is the standard deviation, and k is the sigma multiplier (typically 3-5).

Measurement model:

MEASURED = INNATE + Cal_Error + Thermal_Effect + FW_Effect + Noise

Escape criterion (defective part passes test):

|MEASURED - μ| < kσ  AND  |TRUE - μ| > defect_limit × σ

Simulation Controls

  • Preset Scenarios: Ultra Stable Backend, Mix Change Shock, Tester Degradation Drift, High Variance Chaos, Firmware Mode Switching, Custom Configuration.
  • Lot Parameters: Number of lots (20-500), units per lot (50-1000), baseline mean and sigma for the measured parameter.
  • SPAT Training Lots: Number of initial lots used to calculate static limits (10-100).
  • DPAT Window Size: Rolling window of recent lots for dynamic limit calculation (3-50).
  • k-factor: Sigma multiplier for control limits (2-5). Lower = tighter limits, more fallout.
  • Defect Limit: Sigma multiplier defining true defects (3-6).
  • DPAT Mode: Unstratified (global limits) or Stratified (limits matched by firmware/thermal/tester conditions).
  • Intermittent Defect Rate: Probability of units exhibiting intermittent failures (0-0.5).

What to Observe

  • SPAT vs DPAT Performance: Compare fallout rates, escape rates, and false reject counts between the two methods. DPAT typically adapts better to drift but can be unstable with small windows.
  • Mix Change Shock: Watch how SPAT limits become invalid when the process shifts, while DPAT gradually adapts its limits.
  • Tester Degradation: See how gradual calibration drift affects both methods differently. SPAT may miss the drift entirely.
  • Stratification Benefits: Compare unstratified vs. stratified DPAT to see how accounting for test conditions reduces false rejects.
  • Fallout vs. Escape Trade-off: Tightening k-factor reduces escapes but increases fallout (good parts rejected). Find the optimal balance.

Supply Chain Graph Editor

The simulation includes a visual node graph editor representing the semiconductor backend supply chain. Each node type models a different process step:

  • Material Source: Baseline variability of incoming wafers/dies.
  • Assembly Equipment: Die attach, wire bonding, and packaging variation.
  • Tester: Measurement system with calibration, thermal, and firmware effects.
  • Firmware Mode: Different test software variants with distinct measurement biases.
  • Transport: Physical handling and ESD damage risks.
  • Ship / Destruction: Terminal nodes for accepted and rejected units.
