SPAT vs DPAT
in Backend Semiconductor Assembly & Test

A simulation-driven interactive analysis of Static vs Dynamic Part Average Testing methodologies for backend assembly and test operations

Backend part average testing (PAT) is widely used to screen parametric outliers and contain excursion risk. Two practical strategies exist: Static PAT (SPAT), which derives limits from high-volume historical populations, and Dynamic PAT (DPAT), which continuously updates limits from recent rolling windows. This whitepaper demonstrates—via a graph-based simulation—that backend environments often violate the equivalence assumptions required for DPAT to remain stable, due to stacked variability from materials, assembly equipment, firmware variants, thermal conditions, tester routing, and measurement-chain degradation. We evaluate both methods using escape rate (missed true defects) and fallout rate (false rejects / overkill), and propose a hybrid deployment guideline.

Executive Summary

Key findings from comprehensive PAT methodology analysis

Key Takeaways

  • 1 DPAT assumes equivalence between recent lots — an assumption frequently violated in high-mix backend operations
  • 2 Material changes, tester routing, and firmware switching can create distribution transitions that DPAT "learns" instead of screening
  • 3 SPAT provides baseline stability through robust population statistics and is less sensitive to short-term instability
  • 4 DPAT is valuable as a fast local detector, especially when stratified by tester / thermal / firmware condition
  • 5 The best practical approach is a Hybrid PAT framework: SPAT gate + DPAT diagnostic layer, dynamically enabled based on stability metrics

SPAT vs DPAT Comparison

Attribute SPAT DPAT
Limit Calculation Global baseline (high-volume historical) Rolling window baseline (recent lots)
Baseline Stability High Medium to Low
Responsiveness Lower High
Sensitivity to Mix Shifts Low High
Fallout Risk Lower stability risk, may overkill during qualified shifts Can oscillate; overkill possible during transitions
Escape Risk Higher during early stage (low volume) Higher if rolling baseline absorbs shift
Best Use Primary production screening Targeted diagnostics / stable zones

Key Insight

DPAT becomes unreliable when backend operations violate equivalence assumptions. In backend assembly and test, lot-to-lot distributions can change due to material sources, equipment drift, firmware switching, thermal scaling, and tester degradation. Under these non-stationary conditions, DPAT rolling limits may track transitions and noise rather than isolate true defects. SPAT's stable baseline remains more predictable for high-reliability screening.

Methods & Formulas

Mathematical foundations and simulation parameters

SPAT (Static Part Average Testing)

LimitSPAT = median(lot) ± k × MAD(lot)

Where MAD is the Median Absolute Deviation, providing robust outlier detection independent of distribution assumptions. The factor k typically ranges from 3 to 6 depending on required stringency.

Robust to outliers No history required Distribution-free

DPAT (Dynamic Part Average Testing)

LimitDPAT = μhist ± k × σhist

Where μhist and σhist are calculated from a rolling window of historical lots. Assumes normal distribution and process stability for valid limit calculation.

Tighter limits possible Requires stable history Assumes normality

Reference Implementation

// PAT Limit Calculation Functions

function calculateSPATLimits(lotData, k = 5) {
    const sorted = [...lotData].sort((a, b) => a - b);
    const median = getMedian(sorted);
    const mad = getMAD(sorted, median);

    return {
        upper: median + k * mad * 1.4826,  // Scale factor for normal equiv.
        lower: median - k * mad * 1.4826,
        median: median,
        mad: mad
    };
}

function calculateDPATLimits(historicalLots, k = 4) {
    const allValues = historicalLots.flat();
    const mean = allValues.reduce((a, b) => a + b, 0) / allValues.length;
    const stdDev = Math.sqrt(
        allValues.reduce((sq, n) => sq + Math.pow(n - mean, 2), 0) / allValues.length
    );

    return {
        upper: mean + k * stdDev,
        lower: mean - k * stdDev,
        mean: mean,
        stdDev: stdDev
    };
}
